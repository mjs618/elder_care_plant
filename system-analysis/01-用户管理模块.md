# 用户管理模块分析

## 1. 模块概述

用户管理模块是系统的基础模块，负责用户认证、授权、角色管理和权限控制。采用RBAC（基于角色的访问控制）模型，支持细粒度的资源权限管理。

## 4. 数据模型

### 4.1 核心实体

```python
class User(Base):
    __tablename__ = "users"
    
    id = Column(Integer, primary_key=True, index=True)
    username = Column(String(50), unique=True, index=True, nullable=False)
    email = Column(String(100), unique=True, index=True, nullable=False)
    hashed_password = Column(String(255), nullable=False)
    full_name = Column(String(100), nullable=False)
    phone = Column(String(20))
    avatar = Column(Text, nullable=True)
    role = Column(String(20), nullable=False, default="PATIENT")
    is_active = Column(Boolean, default=True)
    is_superuser = Column(Boolean, default=False)
    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
    
    # 关系
    patients = relationship("Patient", back_populates="caregiver")
    user_roles = relationship("UserRoleAssignment", back_populates="user")

class Role(Base):
    __tablename__ = "roles"
    
    id = Column(Integer, primary_key=True, index=True)
    name = Column(String(50), unique=True, nullable=False)
    display_name = Column(String(100), nullable=False)
    description = Column(String(200))
    is_active = Column(Boolean, default=True)
    created_at = Column(DateTime, default=datetime.utcnow)
    
    # 关系
    user_roles = relationship("UserRoleAssignment", back_populates="role")
    role_permissions = relationship("RolePermission", back_populates="role")

class Permission(Base):
    __tablename__ = "permissions"
    
    id = Column(Integer, primary_key=True, index=True)
    name = Column(String(100), unique=True, nullable=False)
    display_name = Column(String(100), nullable=False)
    description = Column(String(200))
    permission_type = Column(String(20), nullable=False)  # read, write, delete, execute
    is_active = Column(Boolean, default=True)
    
    # 关系
    role_permissions = relationship("RolePermission", back_populates="permission")
    resource_permissions = relationship("ResourcePermission", back_populates="permission")

class Resource(Base):
    __tablename__ = "resources"
    
    id = Column(Integer, primary_key=True, index=True)
    name = Column(String(100), unique=True, nullable=False)
    display_name = Column(String(100), nullable=False)
    resource_type = Column(String(20), nullable=False)  # page, api, menu, button
    path = Column(String(255))
    component = Column(String(100))
    icon = Column(String(50))
    sort_order = Column(Integer, default=0)
    parent_id = Column(Integer, ForeignKey("resources.id"))
    is_active = Column(Boolean, default=True)
    
    # 关系（树形结构）
    parent = relationship("Resource", remote_side=[id], back_populates="children")
    children = relationship("Resource", back_populates="parent")
```

## 6. 评估分析

### 6.1 优点

1. **RBAC模型完善**: 采用标准的RBAC模型，支持用户-角色-权限三层结构
2. **资源类型丰富**: 支持页面、API、菜单、按钮等多种资源类型
3. **树形资源结构**: 资源支持父子关系，便于组织菜单结构
4. **JWT认证**: 使用JWT Token进行无状态认证，适合分布式部署
5. **权限指令**: 前端实现了权限指令，便于UI层面的权限控制

### 6.2 问题与风险

| 问题 | 严重程度 | 描述 |
|------|----------|------|
| 密码存储安全性 | 中 | 需确认使用bcrypt等安全哈希算法 |
| Token刷新机制 | 中 | 缺少Token自动刷新的前端实现 |
| 权限缓存 | 低 | 权限变更后需要重新登录才能生效 |
| 用户角色冗余 | 低 | User表有role字段，同时又有user_roles关联表 |

## 7. 优化建议

### 7.1 安全性优化

```python
# 建议使用bcrypt进行密码哈希
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def hash_password(password: str) -> str:
    return pwd_context.hash(password)

def verify_password(plain_password: str, hashed_password: str) -> bool:
    return pwd_context.verify(plain_password, hashed_password)
```

### 7.2 Token刷新机制

```javascript
// 前端建议实现Token自动刷新
// frontend-vue/src/utils/request.js
let isRefreshing = false
let failedQueue = []

axiosInstance.interceptors.response.use(
  response => response,
  async error => {
    if (error.response?.status === 401 && !error.config._retry) {
      if (isRefreshing) {
        return new Promise((resolve, reject) => {
          failedQueue.push({ resolve, reject })
        })
      }
      
      isRefreshing = true
      error.config._retry = true
      
      try {
        const response = await axiosInstance.post('/api/auth/refresh')
        const newToken = response.data.access_token
        localStorage.setItem('token', newToken)
        
        failedQueue.forEach(prom => prom.resolve())
        failedQueue = []
        
        return axiosInstance(error.config)
      } catch (refreshError) {
        failedQueue.forEach(prom => prom.reject(refreshError))
        failedQueue = []
        router.push('/login')
        return Promise.reject(refreshError)
      } finally {
        isRefreshing = false
      }
    }
    return Promise.reject(error)
  }
)
```
